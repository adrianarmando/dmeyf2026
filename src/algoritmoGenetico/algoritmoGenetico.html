1. Resumen Ejecutivo y Rol en el Workflow

En el pipeline de minería de datos bancarios (Workflow Analista Jr), la etapa de Feature Engineering Intra-mes (FE Intra-mes) crea nuevos atributos combinando variables registradas dentro del mismo período mensual, sin incorporar dependencias temporales (lags o diferencias históricas).

Frente al enfoque tradicional basado en fórmulas fijas dictadas por intuición de negocio humana, esta implementación incorpora Programación Genética Gramatical (Grammatical Evolution) para explorar sistemáticamente el espacio de hipótesis de combinaciones no lineales.

3. Arquitectura y Mecánica Detallada Paso a Paso

1 Selección y Filtrado de Variables Terminales

El pool de terminales se genera dinámicamente a partir de las columnas del dataset bancario tras Catastrophe Analysis y Data Drifting, aplicando tres filtros de seguridad:

  • Exclusión de Metadatos y Target: Se descartan numero_de_cliente, foto_mes, clase_ternaria, clase01, azar, fold_train y fold_final_train.
  • Filtro de Tipo Numérico: Se exige is.numeric == TRUE.
  • Exclusión de Fechas: Se filtran patrones de fecha (prefijos o sufijos fecha o _f).
  • Control de Cardinalidad: Si quedan más de 60 variables, se toma una muestra determinística de tamaño 60 con set.seed(PARAM$semilla_primigenia).

2 Split Local Temporal y Blindaje Anti-Data-Leakage

Para evitar sobreajuste y contaminación de las fases posteriores de validación y test oficial:

  • Aislamiento Temporal: Se utilizan únicamente meses estrictamente anteriores a 202107. La validación local del GA (idx_val_GA) toma los últimos 3 meses disponibles (ej. 202104, 202105, 202106), y el entrenamiento (idx_tr_GA) toma los meses precedentes.
  • Submuestreo Estratificado: Se restringe la evaluación a $50.000$ filas de entrenamiento y $25.000$ de validación, alcanzando una velocidad de cómputo de ~3-5 ms por individuo.
  • Vectores Objetivo Aislados: y_tr_GA e y_val_GA se instancian en memoria RAM como vectores de enteros, sin anexar columnas a dataset, impidiendo la filtración de target en el posterior paso de lags.

3 Operadores Aritméticos Protegidos

Para garantizar estabilidad matemática absoluta y prevenir que divisiones por cero o valores negativos generen NaN o Inf:

protected_div <- function(x, y) {
  res <- x / (y + 1e-5)
  res[is.na(res) | is.infinite(res)] <- 0
  res
}

protected_log_diff <- function(x, y) {
  res <- log(abs(x - y) + 1)
  res[is.na(res) | is.infinite(res)] <- 0
  res
}

es_expresion_trivial <- function(f) {
  !grepl("[+*/-]|protected_", f)
}

La función es_expresion_trivial() detecta si el genoma degeneró en una variable simple sin operaciones (ej: ctrx_quarter), descartándola para reservar los cupos a combinaciones no lineales reales.

4 Gramática Formal BNF (Backus-Naur Form)

Se construye un archivo temporal que define la sintaxis formal del lenguaje algebraico permitido:

<expr> ::= <op>
<op>   ::= <op> + <op> | <op> - <op> | <op> * <op> | 
           protected_div(<op>, <op>) | protected_log_diff(<op>, <op>) | <var>
<var>  ::= ctrx_quarter | mcuentas_saldo | Visa_msaldototal | ...

Los codones enteros del genoma mapean cada regla de derivación determinando qué operador o terminal se expande recursivamente hasta un árbol terminal de profundidad máxima 10.

5 Función de Aptitud (Fitness) con LightGBM Univariado Real

El valor de aptitud no es una correlación lineal simple ni una prueba de chi-cuadrado; se mide la discriminabilidad univariada real entrenando un modelo LightGBM:

fitness_gramEvol <- function(expr) {
  valores <- tryCatch(eval(expr, envir = dataset), error = function(e) NULL)
  if (is.null(valores)) return(1)

  val_tr <- valores[idx_tr_GA]
  val_finitos <- val_tr[is.finite(val_tr)]
  if (length(val_finitos) == 0 || length(unique(val_finitos)) <= 1) return(1)

  dtr_ga  <- lgb.Dataset(data = matrix(val_tr, ncol = 1), label = y_tr_GA, free_raw_data = TRUE)
  dval_ga <- lgb.Dataset(data = matrix(valores[idx_val_GA], ncol = 1), label = y_val_GA, free_raw_data = TRUE)

  modelo_ga <- tryCatch({
    lgb.train(
      params = list(objective = "binary", metric = "auc",
                    learning_rate = 0.1, num_threads = 1, verbosity = -1),
      data = dtr_ga, valids = list(valid = dval_ga),
      nrounds = 50, early_stopping_rounds = 10, verbose = -1
    )
  }, error = function(e) NULL)

  if (is.null(modelo_ga) || is.null(modelo_ga$best_score) || is.na(modelo_ga$best_score)) return(1)

  1 - modelo_ga$best_score # Costo = 1 - AUC
}

La minimización del costo equivale a maximizar el AUC sobre los meses de validación local.

6 Ciclo Evolutivo y Presión Selectiva Calibrada

El motor evolutivo GrammaticalEvolution() ejecuta las 50 generaciones aplicando una configuración robusta:

  • Elitismo al 50% (75 individuos): Conserva las mejores soluciones halladas impidiendo que mutaciones destructivas degraden el frente óptimo.
  • Tasa de Mutación al 15%: Estimula la exploración en el espacio combinatorio para escapar de mínimos locales.
  • Parada Temprana por Costo: terminationCost = 0.10 (se detiene si se descubre una feature univariada con AUC $\ge 0.90$).

7 Decodificación Paralela y Extracción del Top 20

Finalizado el bucle generacional, se analiza la población completa utilizando multiprocesamiento (mclapply en Linux con detectCores() - 1):

  1. Se decodifica el fenotipo de cada genoma mediante GrammarMap().
  2. Se ordenan los individuos descendentemente por AUC univariado.
  3. Se descartan fórmulas con $\text{AUC} \le 0.50$ (sin poder discriminante).
  4. Se descartan expresiones triviales y duplicados algebraicos.
  5. Se evalúan y materializan en el dataset las 20 mejores columnas únicas con nomenclatura estándar:
    dataset[, GA_Feature_1 := eval(formula_1)] ... dataset[, GA_Feature_20 := eval(formula_20)]

5. Sinergia con las Etapas Posteriores

La inyección de estas 20 features en el dataset no concluye en la etapa intra-mes. Al ingresar en la etapa 9.3.1.5 (FE Histórico):

  • Cada una de las 20 GA_Feature_X es reconocida automáticamente por cols_lagueables.
  • Se calculan sus versiones de retardo temporal: lag1, lag2, delta1 y delta2.
  • De esta manera, el modelo final LightGBM tiene a su disposición no solo las interacciones contemporáneas descubiertas por la evolución, sino también la aceleración y tendencia temporal de las mismas a lo largo de los meses.
